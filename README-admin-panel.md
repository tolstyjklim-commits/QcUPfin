# Админ-панель QcUp: инструкция по настройке

Панель это один файл `panel.html`. Через неё вы принимаете и отклоняете заявки на вывод и смотрите всё об игроках: пополнения, выводы, историю игр и баланса, PnL и итог «в плюсе ли казино».

Сейчас панель работает с Cloudflare Worker (тестовый режим). Данные игроков лежат в базе Worker, а копия профилей пишется в приватный репозиторий GitHub.

## Что нужно заранее

1. Worker уже выложен через GitHub Actions (файл `.github/deploy-worker.yml`).
2. В секретах репозитория (Settings → Secrets and variables → Actions) задан **`ADMIN_KEY`**. Это длинный случайный пароль от панели, минимум 24 символа. Придумайте его сами и нигде не публикуйте.
3. Вы знаете адрес Worker. Он вида `https://qcup-pay.<имя>.workers.dev`. Его пишет Actions в итогах запуска деплоя, строка «Адрес сервера платежей».

Если вы меняли `ADMIN_KEY`, запустите деплой Worker заново, иначе сервер останется со старым ключом.

## Шаг 1. Где открывать панель (в полном тестовом архиве панель уже лежит на сайте, этот шаг можно пропустить)

Админка не должна лежать на сайте игры. Поэтому она идёт отдельным архивом `QcUp-admin.zip`, а в основном проекте (`QcUp-new.zip`) её нет. Не копируйте `panel.html` и `admin.html` в папку `frontend/public` игры: они попадут на сайт игроков.

Есть два варианта. Для тестов подойдёт любой.

### Вариант А. Открывать с компьютера (рекомендую, GitHub не нужен)

1. Распакуйте `QcUp-admin.zip` у себя на компьютере.
2. Откройте `panel.html` в браузере двойным кликом.
3. Разрешите такой способ входа в Worker. В `worker/wrangler.toml` впишите `ADMIN_ORIGIN = "null"`. Так браузер называет страницу, открытую с диска.
4. Запустите деплой Worker (GitHub → Actions → Deploy Worker → Run workflow).

Плюс: панель лежит только у вас, никто её не увидит. Минус: открывать её можно только с этого компьютера.

### Вариант Б. Выложить на GitHub, чтобы открывать с любого устройства

Это нужно, если хотите заходить в панель с телефона или другого компьютера. Панель при этом загружается на GitHub, но **в отдельный репозиторий**, не в репозиторий с игрой.

1. На GitHub создайте новый репозиторий, например `qcup-admin`. Не используйте репозиторий игры.
2. Загрузите в него файл `panel.html` из архива и переименуйте его в `index.html`. Больше ничего не нужно.
3. В репозитории откройте Settings → Pages. В пункте Source выберите «Deploy from a branch», ветку `main` и папку `/ (root)`. Сохраните.
4. Через минуту сайт заработает по адресу `https://<ваш-логин>.github.io/qcup-admin/`. Это и есть адрес вашей панели.
5. В `worker/wrangler.toml` впишите адрес **без пути**: `ADMIN_ORIGIN = "https://<ваш-логин>.github.io"`. Если используете и вариант А, перечислите оба через запятую: `"null, https://<ваш-логин>.github.io"`.
6. Запустите деплой Worker.

Что важно знать про вариант Б:

- На бесплатном GitHub страницы работают только из публичного репозитория, значит адрес панели будет доступен всем, кто его знает. В файле нет ни паролей, ни данных игроков: ключ вы вводите на экране входа, а данные приходят от Worker только после проверки ключа. Но поэтому `ADMIN_KEY` должен быть длинным и случайным, а адрес лучше не публиковать.
- Если у вас платный GitHub, репозиторий можно сделать приватным и включить Pages из него.
- Старую `admin.html` на GitHub выкладывать не нужно. Она нужна только для кошельков и `config.json`.
- Репозиторий `qcup-data` с профилями игроков (шаг 3) всегда приватный и никак не связан с этим репозиторием.

Закрыто всё ключом `ADMIN_KEY`: без него Worker ничего не отдаёт. `ADMIN_ORIGIN` только разрешает браузеру обратиться к Worker с этой страницы.

## Шаг 2. Войти

1. Откройте панель (файл `panel.html` или адрес из варианта Б).
2. В первое поле вставьте адрес Worker (без слэша в конце).
3. Во второе поле вставьте `ADMIN_KEY`.
4. Нажмите «Войти».

Ключ запоминается только на время вкладки. Если закрыть вкладку, при следующем открытии его придётся ввести снова. Кнопка «Выйти» стирает его сразу.

Кнопка «Демо без сервера» показывает панель на выдуманных данных. Ничего никуда не отправляется, это удобно для знакомства.

## Шаг 3. Включить копию данных в GitHub (по желанию)

Нужна, если хотите видеть профили игроков как файлы в репозитории.

1. Создайте **приватный** репозиторий `qcup-data` и положите в него любой файл, чтобы появилась ветка `main`. Репозиторий не должен быть публичным: там будут Telegram ID и адреса кошельков.
2. GitHub → Settings → Developer settings → Fine-grained tokens. Создайте токен с доступом только к `qcup-data` и правом **Contents: Read and write**.
3. В репозитории с игрой добавьте секрет `DATA_GITHUB_TOKEN` с этим токеном.
4. В `worker/wrangler.toml` укажите `DATA_REPO = "<логин>/qcup-data"`.
5. Запустите деплой Worker.

Проверка: на вкладке «Сводка» строка «Зеркало в GitHub» должна показывать «настроено». Кнопка «Записать профили в GitHub сейчас» сразу пишет файлы `players/<id>.json`.

## Как работать с панелью

**Выводы.** Новые заявки на вкладке «Выводы». Для каждой видно игрока, сумму, куда выводить (адрес кошелька или Telegram Stars) и красные пометки, если данные игрока не сходятся. Дальше:

1. Откройте профиль игрока и проверьте вкладки «Итог для казино», «PnL» и «Игры».
2. Если всё в порядке, отправьте выплату со своего кошелька вручную. Для Stars Telegram не даёт боту переводить звёзды напрямую, поэтому их тоже отправляете вы, например подарком на нужное число звёзд.
3. Нажмите «Принять». В поле рядом можно записать номер транзакции.
4. Чтобы отказать, нажмите «Отклонить» и при желании напишите причину. Монеты вернутся игроку автоматически.

Решение по заявке принимается один раз. Повторное нажатие ничего не изменит.

**Список игроков.** Поиск по Telegram ID, имени или @username. Колонки: баланс, пополнено, выведено, поставлено, PnL игрока. Сортировка по активности, пополнениям, ставкам, PnL, выводам и балансу. По клику открывается профиль.

**Профиль игрока (вкладки).**

| Вкладка | Что внутри |
| --- | --- |
| Итог для казино | Главный вердикт простыми словами: казино в плюсе или в минусе, если игрок заберёт всё. Расчёт по строкам, пополнения по способам, все пополнения и выводы |
| Обзор | Ключевые цифры, заметка об игроке |
| PnL | Динамика итога игрока по дням, играм и часам, лучший и худший день, просадка |
| Статистика | Откуда пришли монеты в процентах, куда ушли, графики |
| Игры | Разбивка по играм и полная история ставок и выигрышей |
| Баланс | Лента всех операций с балансом |
| Деньги | Пополнения, бонусы, выводы, кошельки |
| Профиль | Все поля и сырые данные |

## Как читать цифры

**Итог для казино = пополнил − выведено − ждёт вывода − сейчас на балансе.** Это сумма, которую казино заработает или потеряет, если игрок заберёт всё. В расчёте только реальные деньги. Рефералы, бонусы за вход, продажа подарков, ставки и выигрыши не входят, это монеты внутри игры.

Важно понимать, чему можно верить:

- **Проверено сервером:** пополнения, выводы, рефбонусы, возвраты.
- **Присылает приложение игрока:** ставки, выигрыши, бонусы за вход, продажа подарков, баланс. Подделать их технически можно. Поэтому на заявках стоят красные пометки, например «нет пополнений» или «больше пополнений и чистого выигрыша».
- Статистика копится только с момента, когда новая версия Worker и приложения заработала. Прошлые игры восстановить нельзя.

Перед настоящими деньгами игровую логику нужно перенести на сервер, иначе цифры игр остаются «со слов» приложения.

## Безопасность

- Держите `ADMIN_KEY` в секрете, не отправляйте его в чаты и не вставляйте в репозиторий. Если он мог утечь, поменяйте секрет и запустите деплой заново.
- Не выкладывайте панель на сайт игры. Если используете вариант Б, держите её в отдельном репозитории и не публикуйте адрес. Без ключа панель ничего не показывает.
- Репозиторий `qcup-data` держите приватным, токен давайте с минимальными правами.
- Не входите в панель с чужих или общих компьютеров.

## Если что-то не работает

| Что видите | Что делать |
| --- | --- |
| «Неверный ключ» | Ключ не совпадает с секретом `ADMIN_KEY`. Проверьте секрет и перезапустите деплой Worker |
| «Адрес должен начинаться с https://» | Вставьте адрес Worker целиком, без пробелов и без слэша в конце |
| «Нет связи с сервером» | Проверьте адрес Worker. Если адрес верный, проверьте `ADMIN_ORIGIN` в `wrangler.toml` (шаг 1) и перезапустите деплой Worker |
| В списке нет игроков | Игроки появляются после первого входа в игру с новой версией приложения |
| «Зеркало в GitHub: не настроено» | Не заданы `DATA_GITHUB_TOKEN` или `DATA_REPO`, либо не перезапущен деплой |
| Стоит «заявка» у игрока, но на «Выводах» пусто | Нажмите «Обновить» вверху панели |

# Запуск только через GitHub (без сервера)

1. Создайте репозиторий и загрузите содержимое этой папки в корень репозитория.
2. Settings -> Pages -> Source: GitHub Actions.
3. Откройте `admin.html` из отдельного архива `QcUp-admin.zip` (на сайте её нет, это сделано специально), введите адреса кошельков:
   - TON (для TON и USDT в сети TON),
   - TRON (для USDT TRC20),
   затем нажмите «Проверить» у каждого адреса, выберите способы и лимиты.
4. Нажмите «Применить на этом устройстве (тест)», откройте сайт, нажмите «Пополнить» и убедитесь, что окно выглядит как нужно.
5. Нажмите «Скачать config.json», положите файл в `frontend/public/config.json` и сделайте push. Через пару минут Pages пересоберёт сайт, и настройки увидят все игроки.
6. Бот: добавьте Secret `TELEGRAM_BOT_TOKEN` и Variable `WEBAPP_URL` (адрес сайта) и запустите workflow "Run bot". Бот держится до ~6 часов за запуск.
7. В BotFather укажите адрес сайта как Mini App.

Переменные Actions (VITE_TON_ADDRESS и др.) теперь необязательны: они работают как запасной вариант, если config.json нет.

## Как платёж привязывается к игроку
- TON: уникальный комментарий в переводе.
- USDT (TON и TRON): игрок указывает свой кошелёк-отправитель, к сумме добавляется уникальная «копейка» (до 0,01 USDT). Засчитывается только перевод с этого адреса, на точную сумму и после создания заявки.

## Ограничения режима без сервера
- Баланс хранится в браузере игрока, проверка платежа делается на его стороне, поэтому подделка баланса возможна. Для вывода денег нужен серверный режим (DEPLOY.md).
- Серверный режим (ton.ts) поддерживает TON и USDT в сети TON. USDT TRC20 работает только в режиме без сервера.
- Монеты за платёж приходят, пока сайт открыт; платёж ищется в течение окна оплаты.

## Админ-панель и демо-баланс
- Админка (`admin.html`, `panel.html`) живёт в отдельном архиве `QcUp-admin.zip` и на сайт для игроков не попадает. `demo.html` лежит в `frontend/public` (`/demo.html`).
- Демо-баланс открывается на вашем компьютере при локальном запуске, а на опубликованном сайте только по паролю (задаётся в админ-панели, пункт 6). Игроки пароля не знают.
- Чтобы демо влияло на игру, открывайте его по адресу сайта (например `http://localhost:5173/demo.html`), а не двойным щелчком по файлу: у файла из папки другое хранилище.

- Самый надёжный способ демо: откройте игру по её адресу с `#demo` в конце (например `http://localhost:5173/#demo`). В «Профиле» появится карточка с кнопками демо-пополнения. Работает на любом адресе игры, на опубликованном сайте спросит пароль.

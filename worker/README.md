# Бот и платёжный сервер QcUp (Telegram Stars) на Cloudflare, выкладка через GitHub

Эта папка заменяет старый `bot-repo` (бот через Actions на 6 часов): бот теперь работает всегда, а Stars идут через него же.
Всё делает GitHub Actions: создаёт базу, подставляет адрес сайта, выкладывает Worker и подключает бота (кнопка «🎮 Играть», команда /start).

## Один раз в Cloudflare (dash.cloudflare.com, бесплатно)
1. Зарегистрируйтесь.
2. **Account ID**: страница «Workers & Pages» (или Overview), справа в колонке. Скопируйте.
3. Ключ доступа: My Profile → API Tokens → Create Token (можно шаблон «Edit Cloudflare Workers»). Нужны права (Account): **Workers Scripts: Edit** и **D1: Read** (лучше Edit). Account Resources: ваш аккаунт. Скопируйте токен (показывают один раз).
4. База данных: Storage & databases → D1 → Create database, имя строго `qcup`. Таблицы в ней Worker создаёт сам.

## Один раз в GitHub: четыре секрета
Репозиторий → Settings → Secrets and variables → Actions → New repository secret:
- `CLOUDFLARE_API_TOKEN` токен из шага 3,
- `CLOUDFLARE_ACCOUNT_ID` номер аккаунта из шага 2,
- `BOT_TOKEN` токен бота от @BotFather,
- `ADMIN_KEY` ваш пароль к служебным адресам (длинная случайная строка, потом нужна для журнала).
Адрес сайта подставляется сам: `https://ваш-логин.github.io/имя-репозитория/`. Если сайт на другом адресе, добавьте переменную (вкладка Variables) `WEBAPP_URL` с полным адресом (https, слэш в конце).

## Запуск
Сначала в Settings → Pages включите Source: GitHub Actions и дождитесь, пока сайт откроется.
Потом вкладка Actions → «Deploy bot and payments» → Run workflow. Готово, если все шаги зелёные.
В отчёте запуска (Summary) будет строка «Адрес сервера платежей - https://….workers.dev». Если упадёт шаг «Prepare», в красной строке написано, чего не хватает.

## Подключение сайта к серверу платежей
В репозитории откройте `frontend/public/config.json`, нажмите карандаш и впишите адрес из отчёта:
`{ "apiUrl": "https://qcup-pay.….workers.dev" }`
Commit, через пару минут сайт обновится сам.

## Проверка
1. Напишите боту /start: придёт приветствие с кнопкой «🎮 Играть».
2. В игре «Пополнить» → Telegram Stars → 10 Stars. Оплата настоящая (около 20 центов). ⭐ появятся сами, повторно не зачислятся.
3. Журнал: `curl.exe https://….workers.dev/admin/log -H "Authorization: Bearer ВАШ_ADMIN_KEY"`, одна заявка: добавьте `?memo=qc-xxxxxxxxxxxx`. Живые логи: Cloudflare → Workers & Pages → qcup-pay → Logs.
   События: deposit_created, stars_precheckout, deposit_credited, claimed, duplicate_tx, stars_orphan (деньги списаны, а заявки нет: разобрать вручную), invoice_failed, greet_failed.

## Тексты бота (необязательно)
В `worker/wrangler.toml` можно добавить `BOT_BUTTON_TEXT`, `BOT_WELCOME_TEXT` (HTML), `BOT_WELCOME_IMAGE` (https-ссылка на картинку), как раньше в bot.mjs.

## Важно
- Старый бот (bot.yml, bot.mjs, `npm`-бэкенд на VPS) должен быть выключен: у одного бота либо вебхук, либо опрос, не оба сразу.
- Работают только Stars. TON и USDT при включённом сервере из окна пополнения пропадают.
- Баланс в играх пока хранится в браузере игрока: платёж настоящий и защищённый, но сам баланс можно подделать, пока игры не переехали на сервер. Вывода делать нельзя.
- Stars поступают на баланс бота, вывод делается через настройки бота в Telegram с задержкой Telegram.
- Токен бота хранится только в секретах GitHub и Cloudflare.


## Пополнение через @send, @wallet и @xRocket

Три кассы работают через этот же Worker. Включается каждая отдельно: добавляете её ключ секретом, и способ сам появляется в окне «Пополнить». Нет ключа, нет способа.

| Касса | Где взять ключ | Секрет |
|---|---|---|
| @send (Crypto Pay, бывший CryptoBot) | в боте @send (или @CryptoBot): `/pay` → «Create App» → API Token | `SEND_TOKEN` |
| @wallet (Wallet Pay) | https://pay.wallet.tg/ → создать магазин → API key | `WALLET_API_KEY` |
| @xRocket | в боте @xRocket: Settings → Exchange settings → API token | `XROCKET_TOKEN` |

Секреты задаются так (по одному на каждую включаемую кассу; значение вводится в ответ на запрос и нигде не печатается):

```
cd worker
npx wrangler secret put SEND_TOKEN
npx wrangler secret put WALLET_API_KEY
npx wrangler secret put XROCKET_TOKEN
npx wrangler secret put PAY_HOOK_KEY
```

Через GitHub (workflow «Deploy bot and payments»): добавьте те же имена секретов в Settings → Secrets and variables → Actions (нужны только те, что используете) и запустите workflow заново: он передаст их Worker сам.

Либо Settings → Secrets в Cloudflare (Workers → qcup-pay → Settings → Variables and Secrets). Ключи нельзя класть в `wrangler.toml`, в `config.json` и в репозиторий.

### Курс и лимиты (переменные в `wrangler.toml`, раздел `[vars]`)

- `COINS_PER_USD`: сколько ⭐ игры за 1 доллар (по умолчанию 100, как у USDT). Курс фиксируется в заявке при создании.
- `MIN_USD`, `MAX_USD`: минимум и максимум одного пополнения (по умолчанию 1 и 5000).
- `TTL_MIN`: сколько минут действует счёт (общая настройка, как для Stars).

### Вебхуки (необязательны, но ускоряют зачисление)

Без вебхуков зачисление тоже работает: пока окно открыто, сайт каждые 5 секунд спрашивает сервер, а сервер спрашивает кассу. Если игрок закрыл окно, сервер сверится с кассой при следующем заходе в игру. Вебхук делает то же мгновенно, даже если игрок не заходит.

`<СЕКРЕТ>` это значение `PAY_HOOK_KEY`: придумайте длинную случайную строку (20+ символов, только буквы, цифры, `-` и `_`) и задайте её секретом `PAY_HOOK_KEY` (в GitHub: Settings → Secrets and variables → Actions → New repository secret). Не используйте `WEBHOOK_SECRET`: он меняется при каждом выкладывании, и адрес в кабинете кассы перестанет работать.

- @send: в боте @send → `/pay` → My Apps → ваше приложение → Webhooks → Enable, адрес `https://<ваш-worker>/pay/send/<СЕКРЕТ>`.
- @wallet: в кабинете Wallet Pay указать адрес `https://<ваш-worker>/pay/wallet/<СЕКРЕТ>` (протокол HTTPS с настоящим сертификатом).
- @xRocket: если в настройках приложения в боте есть поле для вебхука, укажите `https://<ваш-worker>/pay/xrocket/<СЕКРЕТ>`. Если нет, вебхук не нужен: работает опрос.

### Как это защищено

- Монеты зачисляются только после того, как сама касса по вашему ключу подтвердила, что счёт оплачен, что он наш (payload / externalId) и что сумма совпала с заявкой. Присланный вебхук сам по себе ничего не зачисляет, он только запускает такую проверку.
- Сумма зачисления берётся из нашей заявки, а не из присланных данных.
- Зачисление идёт один раз на заявку (UPDATE с условием), номер счёта кассы уникален, повторный вебхук или опрос ничего не дублируют.
- Заявку может смотреть и получать только её владелец (вход через Telegram).
- Подписи: @send (`crypto-pay-api-signature`) и @wallet (`WalletPay-Signature`) проверяются; адрес вебхука дополнительно содержит секрет.
- Ключи не попадают в ответы сайту и в журнал.

### Проверка перед запуском (обязательно)

Каждую кассу проверьте реальной оплатой на минимальную сумму (1 USD). У @send есть тестовая сеть: `SEND_API_URL=https://testnet-pay.crypt.bot/api` и приложение, созданное в @CryptoTestnetBot. У остальных тестовый режим включается в их кабинетах.

1. Пополните на минимум, оплатите, убедитесь, что ⭐ пришли один раз.
2. Откройте журнал: `GET /admin/log` (Authorization: Bearer ADMIN_KEY) и найдите события `deposit_created`, `provider_webhook`, `deposit_credited`.
3. Повторно отправьте тот же вебхук (в кабинете кассы или curl) и убедитесь, что ⭐ не удвоились.
4. Создайте счёт и не оплачивайте, дождитесь истечения: ничего не зачисляется.

Названия полей и адреса API касс взяты из их публичной документации; @wallet и @xRocket нужно проверить реальной оплатой отдельно (см. выше), у них в документации меньше деталей, чем у @send.

## Вывод средств, панель админа и данные игроков (тестовый режим)

**Как это работает.** Игрок оставляет заявку, монеты сразу списываются. Вы открываете `panel.html`, смотрите историю игрока и нажимаете «Принять» (после того как вручную отправили выплату на его адрес) или «Отклонить» (монеты вернутся игроку). Деньги автоматически не отправляются.

**Важно.** Пополнения проверяются сервером, а ставки, выигрыши и баланс присылает приложение, и подделать их технически возможно. Поэтому в панели такие данные помечены, а красные пометки на заявке показывают расхождения. Для реальных денег игровую логику надо переносить на сервер.

### 1. Данные игроков в GitHub
1. Создайте **приватный** репозиторий `qcup-data` (в нём будут Telegram ID и адреса кошельков, публичным он быть не может). Добавьте в него любой файл, чтобы ветка `main` существовала.
2. GitHub → Settings → Developer settings → Fine-grained tokens → новый токен: доступ только к `qcup-data`, право **Contents: Read and write**.
3. В репозитории с игрой: Settings → Secrets → Actions → секрет `DATA_GITHUB_TOKEN` = этот токен.
4. В `worker/wrangler.toml` впишите `DATA_REPO = "ваш-логин/qcup-data"` и запустите деплой Worker. В репозитории появятся файлы `players/<id>.json`. Основная база всё равно D1, GitHub служит копией для просмотра.

### 2. Админ-панель
Админка не входит в основной архив и не должна попадать на сайт для игроков. Она лежит в отдельном архиве `QcUp-admin.zip`, там же инструкция `README-admin-panel.md`. Адрес, с которого вы открываете панель, нужно разрешить в Worker через `ADMIN_ORIGIN` в `wrangler.toml` (например `http://localhost:8000`).

### 3. Настройка @send, @wallet, @xRocket
Для каждой кассы получите ключ, добавьте как секрет в GitHub (Settings → Secrets → Actions) и запустите деплой Worker. Касса без ключа в приложении не показывается.
- **@send** (Crypto Pay): в боте @send откройте Crypto Pay → Create App → скопируйте API Token → секрет `SEND_TOKEN`.
- **@wallet** (Wallet Pay): в @wallet откройте Wallet Pay → создайте магазин и API-ключ (нужна проверка магазина) → секрет `WALLET_API_KEY`.
- **@xRocket**: в боте @xRocket откройте xRocket Pay → создайте приложение → API-ключ → секрет `XROCKET_TOKEN`.
- Придумайте длинную случайную строку → секрет `PAY_HOOK_KEY`. Адреса вебхуков после деплоя: `<адрес Worker>/pay/<провайдер>/<PAY_HOOK_KEY>` (точный вид в разделе про крипту выше). Впишите их в настройках приложения у каждого провайдера.

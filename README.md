# QcUp — мини-игры с виртуальными монетами и подарками

Telegram Mini App (React + Vite) и небольшой API (Express + Prisma).

## Что внутри
- **Игры:** апгрейд подарков, ракета (краш), «Шторм» (слот 5×3), быстрые слоты, кейсы, мины, Plinko, блэкджек, особняк.
- **Подарки:** инвентарь, маркет с плавающими ценами, апгрейд с шансом (подарок сгорает при неудаче).
- **Задания:** награда дня с серией на 7 дней и одноразовые задания с прогрессом.
- **Экономика:** монеты и подарки только внутриигровые. Пополнения, вывода и обмена на звёзды, TON или настоящие подарки Telegram нет и быть не должно.

## Запуск
```bash
cd frontend && npm install && npm run dev      # интерфейс
cd backend  && cp .env.example .env && npm install && npx prisma generate && npm run dev   # API (опционально)
```
Для `GET /api/gifts/catalog` нужен `TELEGRAM_BOT_TOKEN`; фронтенд показывает каталог, если задан `VITE_API_URL`.

## Демо-данные для тестов
В `frontend/public/gifts` лежат сгенерированные демо-иконки (SVG, нарисованы для проекта), `catalog.json` с 9 подарками и `nft.json` с 12 вымышленными NFT-коллекциями. Цены NFT в демо колеблются каждые 30 секунд. Реальный импорт (скрипт ниже) перезапишет `catalog.json`, а Gift Asset через бэкенд заменит `nft.json`. Демо можно просто удалить.

## Импорт настоящих подарков Telegram
Игра сама подхватывает `frontend/public/gifts/catalog.json`. Создай его скриптом (нужен токен бота из @BotFather):
```bash
cd frontend
# Windows cmd:   set TELEGRAM_BOT_TOKEN=123:ABC
# PowerShell:    $env:TELEGRAM_BOT_TOKEN="123:ABC"
node scripts/import-gifts.mjs     # или: npm run import-gifts
```
Скрипт вызывает `getAvailableGifts`, скачивает миниатюры в `public/gifts/` и пишет каталог. После перезагрузки страницы подарки появляются на маркете, в кейсах и в апгрейде. Цена в монетах = звёзды × 8 (`STARS_TO_COINS` в `lib.ts`), старые подарки игроков остаются у них в инвентаре. Пример формата: `public/gifts/catalog.example.json`. Подарки внутриигровые и на настоящие не обмениваются.

## NFT-подарки с ценами (автоподгрузка)
Коллекционные подарки подтягиваются из Gift Asset API (флор-цены с Getgems, MRKT, Portals и Tonnel, берётся медиана).
1. Получи ключ у бота @giftasset_api_tokens_bot (условия и лимиты смотри там, возможно платно).
2. В `backend/.env` задай `GIFTASSET_API_KEY=...`. По желанию `NFT_IMAGE_TEMPLATE`, например `https://nft.fragment.com/gift/{slug}-1.webp` (адрес картинок я не проверял, подставь рабочий).
3. В `frontend/.env` задай `VITE_API_URL=http://localhost:4000` (порт как в `backend/.env`).
4. Запусти бэкенд. Фронтенд запрашивает `/api/nft/floors` при старте и раз в 5 минут. На маркете появится вкладка «NFT».
Без бэкенда фронтенд читает `public/gifts/nft.json` (пример формата в `nft.example.json`).
Цена в монетах = флор в TON × 100 (`COINS_PER_TON` в `lib.ts`). NFT в игре тоже внутриигровые, в кейсах не выпадают, участвуют в покупке, продаже и апгрейде.

## Иконки настоящих подарков
Скрипт `npm run import-gifts` скачивает миниатюры и анимированные стикеры (`.tgs`). В крупных окнах (апгрейд, кейс) играет анимация, в списках показывается миниатюра.

## Важные ограничения
- Сейчас баланс, раунды и результаты считаются **на клиенте** и лежат в `localStorage`. Это демо: результат можно подменить в браузере.
- Перед публикацией перенеси кошелёк, ГСЧ и выдачу наград на сервер: проверка `initData` уже есть в `backend/src/telegram.ts`, модели `Wallet` и `Transaction` в Prisma готовы.
- Настоящие подарки Telegram выдавай только за места в рейтинге или задания (`sendGift` с сервера), а не за исход случайной игры. Иначе это азартная игра на ценности и нарушение правил Telegram и законов многих стран.
- Картинки в `frontend/public/games` (корова на ракете, шлем и др.) похожи на персонажей стороннего сервиса. Замени их своими, прежде чем публиковать.

## Математика
Возврат игроку (RTP) заложен в `frontend/src/lib.ts`: ракета 97%, апгрейд 94%, слот «Шторм» около 93%, три барабана около 96%, мины 97%, Plinko около 96%, кейс около 85%.

## Анимации и звук
- Ракета: canvas-сцена (параллакс звёзд, след, пламя, взрыв с тряской экрана, улёт при выводе).
- Кейсы: лента-рулетка с замедлением и тиками. Апгрейд: циферблат со стрелкой, сгорание подарка или золотая вспышка.
- Шторм/слоты: прокрутка лент с остановкой барабанов по очереди. Plinko: прыжки по колышкам. Мины: переворот плиток. Блэкджек: раздача карт.
- Звуки синтезируются в браузере (`src/sfx.ts`), включаются кнопкой звука. Для prefers-reduced-motion анимации сокращены.
- Базовые подарки (мишка, сердце, роза, торт, букет, ракета, шампанское, кубок, кольцо, алмаз) в `public/gifts/90xx.svg` нарисованы мной, это демо-иконки. Настоящий каталог подтягивает `npm run import-gifts`.

## Автовыгрузка подарков при подключении бота
1. В `backend/.env` укажи `TELEGRAM_BOT_TOKEN=токен_из_BotFather`.
2. В `frontend/.env` укажи `VITE_API_URL=http://localhost:4000` (см. `.env.example`).
3. Запусти `npm run dev` в `backend`, затем в `frontend`.

При старте бэкенд сам запрашивает `getAvailableGifts`, скачивает иконки и анимации в `backend/cache/gifts` и обновляет список раз в 30 минут. Игра берёт каталог с `/api/gifts/catalog` и заменяет демо-подарки настоящими. Токен наружу не отдаётся, файлы раздаются с `/gifts-assets`. Если бэкенда или токена нет, игра использует `public/gifts/catalog.json` (демо или результат `npm run import-gifts`).

## Бот с кнопкой запуска
В `backend/.env` задай `WEBAPP_URL=https://...` (адрес фронтенда по HTTPS; для теста с компьютера подойдёт `npx cloudflared tunnel --url http://localhost:5173` или ngrok). При старте бэкенд запускает бота: на `/start` он отправляет плашку с кнопкой «🎮 Играть», которая открывает мини-приложение, и ставит ту же кнопку в меню чата. Текст, подпись кнопки и картинку плашки можно поменять через `BOT_WELCOME_TEXT`, `BOT_BUTTON_TEXT`, `BOT_WELCOME_IMAGE`.

## Запуск одним файлом (Windows)
Дважды кликни **`Запуск QcUp.bat`**. Нужен только Node.js LTS. Файл сам:
- установит зависимости при первом запуске;
- спросит токен бота, если он ещё не сохранён (только в этом окне, в Telegram ничего не спрашивается). Токен проверяется через `getMe` и сохраняется в `backend/.env`; если нажать Enter, игра запустится без бота с демо-подарками;
- сам откроет https-туннель (cloudflared, запасной вариант ssh на pinggy) и пропишет его адрес в `WEBAPP_URL`, так что кнопка в боте работает без ручной настройки (бесплатный туннель живёт около часа, потом перезапусти файл; отключить: `AUTO_TUNNEL=0` в `backend/.env`);
- запустит бэкенд и игру и откроет http://localhost:5173.

Сменить токен: **`Сбросить токен.bat`**, при следующем запуске он спросится заново. Остановить: Ctrl+C или закрыть окно.

## Цены
Цена подарка в монетах равна цене в звёздах (1★ = 1 монета). NFT: 1 TON флора ≈ 150 монет (`COINS_PER_TON` в `frontend/src/lib.ts`). Цены NFT берутся без ключей из открытого датасета флоров Fragment (github.com/Atlannn/telegram-gifts-floor-price, CC BY 4.0, «Telegram gifts floor prices», Baltic Assets, balticassets.eu): обновляется раз в сутки, цены в TON/GRAM. Бэкенд отдаёт их на `/api/nft/floors`, а если бэкенда нет, фронтенд читает файл напрямую. Если задан `GIFTASSET_API_KEY`, бэкенд берёт цены у Gift Asset. Без интернета показываются демо-коллекции.

Названия коллекций: «Telegram Gifts and Stars Dataset» (Gift Club, CC BY 4.0, gift-club.github.io/telegram-gifts-dataset). Иконки коллекций загружаются в браузере игрока со страниц Fragment (адрес задаёт `NFT_IMAGE_TEMPLATE`, значение `none` отключает картинки; если картинка не загрузилась, показывается нарисованный кристалл). Это изображения Telegram: в архив они не включены.

Иконки NFT сохраняются на ПК автоматически при запуске (`frontend/scripts/cache-nft-icons.mjs` → `frontend/public/gifts/nft/`), докачиваются только новые коллекции. В архив проекта они не входят: это изображения Telegram.


## Запуск через GitHub (без своего компьютера)
Игра лежит на GitHub Pages, бот работает в GitHub Actions. Компьютер не нужен.

**1. Игра на GitHub Pages.** Загрузи проект в репозиторий (`.github/workflows/deploy-pages.yml` уже есть). В *Settings → Pages* выбери источник *GitHub Actions*. После пуша в `main` сборка запустится сама, адрес будет `https://<логин>.github.io/<репозиторий>/`. Бэкенда там нет: настоящие подарки берутся из `frontend/public/gifts/catalog.json`, цены NFT из открытого датасета на GitHub.

**2. Бот в отдельном репозитории.** Папка `bot-repo` целиком (вместе с `.github/workflows/bot.yml`) идёт в **другой, лучше приватный** репозиторий. В нём:
- *Settings → Secrets → Actions*: секрет `TELEGRAM_BOT_TOKEN`;
- *Settings → Variables → Actions*: переменная `WEBAPP_URL` = адрес Pages из шага 1 (https, со слэшем на конце);
- вкладка *Actions → Run bot → Run workflow*. Дальше бот перезапускается сам по расписанию раз в 5 часов, новый запуск заменяет старый.

На `/start` бот присылает плашку с кнопкой запуска и ставит ту же кнопку в меню чата. Текст и картинку можно задать переменными `BOT_WELCOME_TEXT`, `BOT_BUTTON_TEXT`, `BOT_WELCOME_IMAGE`.

**Что учесть.**
- Одним токеном бота может пользоваться только один «слушатель». Если локально тоже запущен `Запуск QcUp.bat`, будет ошибка 409 и локальный бот переписывает кнопку на адрес туннеля. Поэтому для режима GitHub поставь `BOT_ENABLED=0` в `backend/.env`: локально игра запустится без бота и без туннеля.
- GitHub Actions создан для сборок, а не для бесконечного хостинга. Бесплатный лимит минут есть только у публичных репозиториев, а у приватных он ограничен (проверь свой тариф), и в неактивных репозиториях расписание отключается через 60 дней. Если нужна надёжность, держи бота на любом дешёвом сервере: `node bot.mjs` с теми же переменными.
- Токен хранится только в секретах GitHub, в код его класть нельзя.

## Что добавлено в играх
Ракета: авто-вывод на выбранном множителе. Мины: выбор числа мин (1–12), коэффициент считается честно. Plinko: три уровня риска. Блэкджек: удвоение ставки. Кейсы: четыре обычных и два NFT-кейса, список содержимого с шансами, быстрое открытие и продажа выпавшего подарка в один клик.

## «Дом всегда в плюсе»
Игра учит тому, что у казино нельзя выиграть в долгую, поэтому у неё есть открытый механизм. Все игры считают, сколько игрок поставил и сколько получил (`stats.gStaked` и `stats.gPaid`). Небольшой плюс разрешён: 300 монет плюс 15% от ставок. Если игрок выигрывает больше, функция `houseTilt` в `lib.ts` постепенно ухудшает шансы (максимум на 30%): ракета вылетает раньше, апгрейд реже удаётся, в слотах повторяется розыгрыш при выигрыше, в кейсах дорогие подарки выпадают реже, в минах иногда «переезжает» мина, шар в Plinko тянет к центру, у дилера в блэкджеке лучше скрытая карта, в особняке приз чаще за другой дверью. Игрок это не видит в момент игры, но под каждой игрой честно написано, что казино всегда в плюсе, а в README механизм описан. Монеты виртуальные, пополнения и вывода нет. Отключить: верни `houseTilt` нулём.
